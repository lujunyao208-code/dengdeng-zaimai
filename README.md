# 等等再买 v1.0 MVP

> 喜欢它没关系，先不用马上拥有它。
> 在每一次「好想买！」的时候，给自己一个再想一想的机会。

移动端消费决策辅助工具（第一版 MVP）。
纯前端静态网页 App：零依赖、无需构建，数据保存在浏览器 localStorage。

## 怎么打开

**电脑上预览（推荐先这样看）：**
直接双击 `index.html`，或用浏览器打开它。
浏览器按 `F12` → 点击「设备工具栏」图标（手机图标），选择 iPhone 尺寸（375×812）查看移动端效果。
页面按 375×812 设计，窗口大于 520px 时自动居中呈现为手机列样式。

**手机上预览：**
手机和电脑连同一个 Wi-Fi，在本目录启动任意静态服务器：

```bash
# 方式一（Windows 自带 Python 时）
python -m http.server 8000

# 方式二（有 Node 时）
npx serve .
```

然后手机浏览器访问 `http://<电脑局域网IP>:8000`。

## 功能清单

| 页面 | 功能 |
| --- | --- |
| 我的物品 | 商品列表、状态徽章（冷静中/已购买/已放弃/继续犹豫）、筛选（全部/冷静中/已购买/已放弃）、冷静期结束提醒横幅、商品详情页（价格一律展示约数） |
| 添加新物品 | 上传截图 → 商品识别（类别优先 + 价格核对，不确定价格不编造）→ 确认/修改类别与价格 → 一次一个问题（4问，含购买欲望滑块）→ 结果页只给结论（评价语 + 冷静 X 天 + 一句话）→ 开始冷静；也支持手动输入商品 |
| 我的 | 头像与昵称（编辑资料页：推荐图标/相册上传）、已花费/已省下的钱、冷静记录、消费偏好（简单版）、设置（冷静期偏好/账号与安全/关于） |

## 核心规则（都集中在 js/config.js）

- 预计使用次数 = 使用频率（次/月） × 预计使用时间（月），限制在 1~1000 次
  - 使用频率：每天 30 / 每周3–6次 18 / 每周1–2次 6 / 每月几次 3 / 偶尔使用 1（次/月）
  - 使用时间：1周左右 0.25 / 1个月左右 1 / 3个月左右 3 / 6个月左右 6 / 1年左右 12 / 1年以上 18（月）
- 单次使用成本 = 商品价格 ÷ 预计使用次数（精确值仅内部计算用，展示一律约数）
- 冷静期为四因素综合（最终 0~5 天，边界严格执行「＞/≤」）：
  - ① 商品总价基础分：≤¥50 → 0天；≤¥100 → 0.5天；≤¥200 → 1天；≤¥300 → 1.5天；≤¥500 → 2天；≤¥800 → 3天；≤¥1200 → 3.5天；>¥1200 → 4天
  - ② 单次使用成本修正：≤¥5 → +0；≤¥20 → +0.5；≤¥50 → +1；>¥50 → +1
  - ③ 购买欲望修正（0–100% 滑块，默认 70%）：≤60% → 0；61–80% → −1；81–100% → −2
  - ④ 使用场景修正：日常使用 → 0；特定场景 → −1；暂时没有明确场景 → 0
  - 相加后四舍五入，限制在 0~5 天
- 结果页只给结论（评价语 + 冷静 X 天 + 「两天后，再决定要不要买。」），不展示计算过程
- 冷静期偏好（我的 → 设置）：标准 / 宽松 / 谨慎 —— 系统照常计算后按偏好整体调整（如谨慎模式下 2天→3天、宽松模式下 2天→1天），结果仍在 0~5 天
- 冷静期结束 → 还是想买（已购买）/ 不买了（已放弃，金额计入省下）/ 还在犹豫（自动再冷静一轮）

## Mock 与待接后端的地方

1. **商品识别（OCR）** — `js/ocr.js` 是 Mock：按图片哈希从模拟商品库返回结果（同一张图结果稳定），并模拟了价格核对（取到手价/券后价，排除划线价、编号、数量）；V1.2 起类别识别优先恢复（只返回「运动鞋」「T恤」这类通用类别名，不识别品牌型号），无法确定价格时返回 `price: null` 并提示「暂未确定准确价格，请确认」，由用户确认页补填，不编造价格。
   以后接真实 OCR/商品识别 API 时，只需替换 `OCRService.recognize()` 内部实现，返回结构保持 `{ name, price, category, confidence, priceNote }`，调用方无需改动；真实实现必须在 prompt 中执行同样的价格核对、类别优先、不确定价格不编造规则。
2. **数据存储** — 目前是浏览器 localStorage（含用户上传头像的 dataURL）。以后接后端时，替换 `js/store.js` 里的读写方法为 API 调用即可（数据结构已按 PRD 的 Product/User 模型设计）。
3. **冷静期结束提醒** — 目前用「我的物品」页顶部横幅 + 卡片状态承担。以后可接浏览器通知 / 服务端推送（V1.1 按文档要求删除了无法真实工作的通知设置入口）。
4. **账号系统** — V1.1 不做真实登录，「账号与安全」为说明页（本地体验模式）；等有后端用户系统后再接。

## 开发调试工具（发布时可移除）

「我的 → 设置 → 关于」页内有三个调试按钮：

- **填充示例数据**：一键生成覆盖各状态的示例商品，快速查看页面效果
- **让所有冷静期立即结束**：不用等 24 小时即可体验「冷静期结束 → 做决定」流程
- **清空全部数据**：重置到初始状态

## 产品决策备忘（与 PRD / V1.1 / V1.2 修改建议的差异点）

1. 冷静期计算按 V1.2 修改建议重做：四因素（商品总价基础分 + 单次成本修正 + 购买欲望修正 + 使用场景修正）相加后四舍五入，限制 0~5 天。
2. 结果页只给结论：评价语 + 「冷静 X 天」+「两天后，再决定要不要买。」，不展示任何计算过程（V1.2）。
3. 展示精度与计算精度分离：界面价格一律显示约数（¥299 → 约 ¥300），单次成本取整（¥5.537 → 约 ¥6/次）；后台保留精确值用于统计与重算。
4. 筛选标签用 **全部｜冷静中｜已购买｜已放弃**；「继续犹豫」商品正在再冷静，归入「冷静中」（已确认）。
5. 「还在犹豫」= **自动再冷静一轮**（同时长冷静期，可反复，已确认）。
6. 「累计冷静时间」：已决定的商品按完整冷静期计，仍在冷静中的按已进行天数计（数据动态变化）。
7. 「没花的钱」与「已省下的钱」为同一数值，只保留一张「已省下的钱」卡片。
8. 设置页遵循「删除入口 > 留假按钮」：通知设置已删除；账号与安全为说明页（本地体验模式，不做真实登录）；冷静期偏好为真实功能（宽松/标准/谨慎，按天映射整体调整）。
9. 0天冷静期的商品加入后立即显示「冷静结束 · 可以决定啦」，随时可做决定。
10. 头像与昵称统一在「我的 → 编辑资料」页修改：推荐线稿图标 + 相册上传（居中裁剪为正方形、压缩后存 localStorage），上传图片优先显示。
11. OCR 识别结果：类别优先恢复为通用类别名（不识别品牌型号）；无法确定价格时不编造，返回「暂未确定准确价格，请确认」由用户补填（V1.2）。
12. 添加页顶部「你今天又被种草了吗？」后的心形图标已去掉（V1.2）。
